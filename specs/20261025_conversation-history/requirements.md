# 要件と方式の決定

## 対象範囲

- `app/ask.py` に同一プロセス内で会話を続けられる対話モードを追加する。
- `tests/test_ask.py` で会話履歴と CLI の動作を検証する。
- README に対話モードの使い方を記載する。
- 会話履歴の方式と、今回その方式を選ぶ理由を記録する。

## 背景と目的

現状の `app/ask.py` は質問1回で終了するため、前の質問・回答を踏まえた追加質問ができない。講座の実装課題として、モデルに会話の文脈を渡す方法と、その履歴が入力トークン数に与える影響を学べるようにする。

## 制約と評価軸

方式は、次の観点で比較する。

1. **既存構成との整合性** — 固定中の SDK や `generate_content` 呼び出しを活かし、依存追加・API移行を避けられるか。
2. **学習上の見通し** — どの質問・回答が次のリクエストに含まれるかを受講者が確認できるか。
3. **保存要件への適合** — 会話をプロセス内だけで扱う要件に合い、不要な永続化を持ち込まないか。
4. **実装・検証の規模** — 既存の単発実行を保ち、API通信をモックして動作をテストできるか。

## 決定事項

- 引数なしで起動した場合は対話モードにし、`/exit` または `/quit` まで質問を受け付ける。
- 会話履歴はアプリケーションのメモリ上に持ち、**全ターンの質問と回答**を次の `generate_content` リクエストに含める。
- トークン表示では、過去の会話履歴だけの数を `count_tokens` で計数し、生成APIの利用量メタデータが返す入力全体（履歴＋今回の質問）・出力と並べて表示する。履歴がない最初の質問では履歴トークン数を0とし、計数APIを呼び出さない。
- 履歴の個別計数には履歴のある各質問で追加の `count_tokens` APIリクエストが必要となる。これは会話生成とは別の計数リクエストであり、生成APIへの実入力トークン数も従来どおり表示する。
- プロセス終了後に履歴は保存・復元しない。履歴をモデルへ送信することと、サーバー側の会話セッションとして保存することは区別する。
- 既存の質問引数による単発実行、`--temperature`、モデル表示、トークン表示、APIエラー処理を維持する。
- 今回は履歴の圧縮、切り詰め、要約、外部保存を追加しない。

## 方式の選択と理由

### 採用: アプリが全履歴を明示して `generate_content` に渡す

現在の `google-genai` SDK と `generate_content` 呼び出しを再利用でき、追加依存やAPI移行が不要である。`types.Content` の履歴を組み立てるため、次のリクエストに何を含めるかがコードとテストに明示され、会話文脈の仕組みを学ぶ課題に合う。保存範囲も同一プロセス内に限定できる。

### 今回は採らない方式

- **SDK の `Chat`**: SDK が質問・回答のターンを管理するため、対話ループは簡潔になる。履歴は `get_history()` で確認できるが、毎回のリクエスト内容をアプリ側で組み立てる方式より、履歴を送る仕組みが抽象化される。今回は既存の呼び出しを活かし、受講者が履歴の構造を直接確認することを優先する。
- **Interactions API のサーバー側継続**: 前回の Interaction ID を使ってサーバーに保存された会話を続けられる。しかし今回の要件はプロセス内だけの履歴であり、API移行やサーバー保存の要否・保持方針を追加で決める必要があるため、対象を超える。
- **LangChain などの履歴フレームワーク**: 会話の保存や要約などの機能を提供するが、短い対話 CLI のために新しい依存・抽象化を導入する必要はない。フレームワーク自体の利用が要件になった場合に改めて比較する。

## 圧縮を今回行わない理由と再検討条件

全履歴を送る方式では、会話が長くなるほど入力トークン数が増え、費用・応答時間やコンテキスト上限に影響する。一方、この機能は短い学習用 CLI であり、既存のトークン表示を使って増加を観察できる。最初から圧縮を加えると、履歴を保持する基本動作と、履歴を選別・変換する動作を同時に学ぶことになるため、まずは全履歴にする。

実際に入力トークン量や上限が問題になったら、要件を再確認し、直近ターンの切り詰め、トークン予算による切り詰め、要約＋直近ターンを比較する。過去の発言の再現が必要か、古い決定や前提だけ残せばよいかを基準に選び直す。プロセスをまたぐ記憶が必要になった場合は、圧縮とは別に永続化・検索方式を検討する。
