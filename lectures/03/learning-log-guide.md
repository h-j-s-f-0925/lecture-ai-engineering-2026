# 講義・演習・宿題のプロンプト結果を学習記録に保存する

この手順では、これまでの講義資料にあるプロンプトを実行し、質問と実際の出力を集めてから、1つの学習記録にまとめて保存します。

## 仕組みと準備

この手順で使う `uv run python -m app.agent "質問"` は、質問を1つ処理して終了します。次にコマンドを実行しても、前の質問や回答は会話履歴として自動では引き継がれません。また、回答が自動で学習記録に保存されるわけでもありません。質問と実際の出力を自分でメモファイルに集め、最後にその内容を含めて保存を依頼します。

### メモファイルを作る

1. Codespaces のターミナルで、リポジトリのルートにいることを確認します。

   ```bash
   pwd
   ```

   出力が `/workspaces/lecture-ai-engineering-2026` でなければ、次でリポジトリのルートへ移動します。

   ```bash
   cd /workspaces/lecture-ai-engineering-2026
   ```

2. 次のコマンドで、メモファイルを作ります。既にファイルがある場合は上書きしません。

   ```bash
   if [ ! -e lectures/03/learning-log-input.md ]; then
     printf '%s\n' '# 講義・演習・宿題の実行記録' > lectures/03/learning-log-input.md
   fi
   ```

   `if [ ! -e ... ]` は、指定したファイルがまだ存在しない場合だけ中の処理を行います。`printf` は先頭見出しをファイルへ書きます。ファイルが既にある場合は上書きも消去もしません。

3. 次のコマンドでファイルが作られたことを確認します。

   ```bash
   ls -l lectures/03/learning-log-input.md
   ```

同じターミナルを使い続ける必要はありません。以下の記録コマンドはファイルのパスを直接指定して追記するため、ターミナルを閉じて開き直しても使えます。ターミナルで実行したプロンプトと**実際の出力**を自動でメモファイルへ書きます。Colab上で実行する第2回の結果など、Codespacesのターミナルに出ない結果だけは、VS Codeで `code lectures/03/learning-log-input.md` を実行して開き、手入力または貼り付けてください。実行していない出力を作ったり、結果を推測で補ったりしないでください。APIキーや個人情報は記録しないでください。

## 各回のプロンプトを実行する

以下は現在リポジトリにある各回の資料を使う例です。実際に取り組んだ演習・宿題に関係するものを選び、**コマンドだけでなく出力もメモに残します**。プロンプトの出典はそれぞれの `problem.md` です。

### 第1回：素のLLMへの質問

第1回の質問を記録するシェルスクリプトを用意しています。次のコマンドで実行します。

```bash
uv run bash lectures/03/lec01-log.sh
```

スクリプトは4つの質問を順に `app.ask` へ渡します。各質問の実行日時・コマンド・結果はターミナルに表示されると同時に `lectures/03/learning-log-input.md` へ追記されます。追記なので、2回目以降に実行すると結果が追加されます。ある質問でエラーが起きても、そのエラーを記録して残りの質問を続けます。4問をすべて試した後、1つでも失敗があればエラー終了します。4回分のAPI呼び出しが発生するため、記録したい質問だけを実行してください。

記録されたかどうかは、次のコマンドで確認できます。

```bash
tail -n 40 lectures/03/learning-log-input.md
```

`uv run python -m app.ask` を引数なしで起動すると対話できますが、これは第1回の「素のLLM」であり、`save_learning_log` ツールを持っていません。この手順では質問ごとの実行結果をメモし、最後に第3回のAgentへ渡して保存します。

### 第3回：エージェントへの質問とツール呼び出し

第3回の質問を記録するシェルスクリプトを用意しています。次のコマンドで実行します。

```bash
bash lectures/03/lec03-log.sh
```

スクリプトは `uv run python -m app.agent --trace "LoRAとQLoRAの違いは？"` を実行します。回答だけでなく `[tool call]` と `[usage]` もターミナルに表示し、同じ出力を `lectures/03/learning-log-input.md` へ追記します。既存の記録は消しません。スクリプトをもう一度実行すると、同じ質問の新しい結果が末尾に追加されます。実装レベルを試す場合は、後述の保存テストとは別に、作った機能の実行結果も記録してください。

### `save_learning_log` の承認・保存を試す

まず動作だけを確かめる場合は、学習内容を具体的に指定して保存を依頼します。`app.agent` は起動ごとに質問を1つ処理するため、このコマンドに保存したい内容を含めてください。モデルは本文 `content` と、記録全体の内容を表す短い `title` を保存ツールへ渡します。

```bash
uv run python -m app.agent "次の学習内容を短いMarkdownの学習記録にまとめ、save_learning_log ツールで保存してください。title には内容の主題が分かる短い日本語タイトルを付けてください。例えば「エージェントとツールの基本」のようにします。content には記録本文を渡してください。学んだこと: エージェントはモデル、ループ、ツールから構成され、モデルがツールを呼び、その結果を使って回答する。気づき: ツールの説明文がモデルの選択に影響する。疑問: 保存のような操作を実行する前に、どう利用者へ確認するのか。"
```

保存ツールが呼ばれると、CLIに保存先と本文が表示されて入力待ちになります。内容を確認して `y` または `yes` を入力すると保存され、拒否する場合は `n` または Enter を入力します。確認が出ずにコマンドが終了した場合は保存されていません。依頼文を明確にして再実行するか、`--trace` を付けて `save_learning_log` が呼ばれたかを確認してください。

承認画面には、保存内容とともにファイル名に使う `title` も表示されます。今回の記録なら「LoRAとQLoRAの質問結果」のように、区分名（「第1回 演習」）ではなく記録全体の主題を表すタイトルにします。保存ファイル名は `YYYYMMDD_HHmm_タイトル.md` の形です。日本語は残し、ファイル名で問題になる記号や空白はハイフンに整えます。同じ分に同じタイトルのファイルがすでにある場合は、上書きせずエラーになります。

複数ターンの会話から保存する場合は、会話と回答を一時メモに記録し、最後の保存依頼にその内容を含めます。`app.agent` の別々の起動間で履歴が自動的に共有されるわけではありません。

## 結果を1つの学習記録として保存する

メモファイルを保存したら、ターミナルでリポジトリのルートにいることを確認し、次のコマンドを実行します。引用符内がAgentに渡すプロンプトです。`$(cat lectures/03/learning-log-input.md)` の部分はシェルがメモファイルの内容に置き換えるため、依頼文と実行記録が1つのプロンプトとして渡されます。最終依頼の出力は元のメモへ追記せず、ターミナルで確認します。実際の保存内容は、次の節の承認画面で表示されます。

```bash
uv run python -m app.agent "以下は、これまでの講義・演習・宿題で実行したプロンプトと実際の結果です。
各回・区分ごとに、実行したことと実際の出力は観察事実としてまとめてください。
「分かったこと」は出力から根拠を示せる範囲で推論し、「結果から読み取れること」と
明記してください。出力だけから本人の感想や理解度を断定してはいけません。
「残った疑問」は記録に質問がある場合だけ列挙し、なければ「記録なし」としてください。
実行していないことや出力にない事実は追加しないでください。
記録全体の主題が分かる短い日本語の title と、まとめたMarkdown本文の content を作り、
save_learning_log ツールで保存してください。title は「第1回 演習」のような区分名ではなく、
記録全体を代表する具体的な主題にしてください。

実行記録:
$(cat lectures/03/learning-log-input.md)"
```

実行して「そのようなファイルやディレクトリはありません」と表示された場合は、手順の最初に戻り、リポジトリのルートにいることと `lectures/03/learning-log-input.md` を保存したことを確認してください。入力が大きすぎてエラーになる場合は、全てを一度に渡さず、対象回を分けて複数の学習記録として保存してください。

## 保存前後の確認

保存ツールが呼ばれると、CLIに保存先と、モデルが作った記録本文が表示されます。

- 内容を確認し、保存してよい場合だけ `y` または `yes` を入力します。
- 内容が違う場合は `n` または Enter で拒否し、`lectures/03/learning-log-input.md` またはプロンプトを直してもう一度実行します。
- 入力を中断した場合は保存されません。

保存が成功したら、最新のMarkdownファイルとGitの状態を確認します。作業用メモも `lectures/03/` にあるため、提出に含めるかを確認してください。不要なら削除して構いません。

```bash
ls -lt learning_log/
git status --short
```

`learning_log/` はGit管理対象です。学習記録を提出に含めるか、提出前に確認してください。

## 補足

- 現在の `lectures/` には第1・2・3・5回の資料があります。第4回の資料はこのリポジトリにはありません。
- コマンド例は各回の資料にあるプロンプトから抜粋しています。実際に行った宿題内容に合わせて選び、未実行の結果を実行済みとして記録しないでください。
- APIを使うコマンドは利用枠を消費します。必要なプロンプトだけ実行し、APIキーを出力やメモに貼らないでください。
