#### 改善した例と、残る失敗・制約

- 改善した例：lora と not-in-materials は、答えを保ったまま入力トークンが約25〜28%、費用が約14〜23%減った
- 悪くなった例：multi-page は、1回の検索で根拠がそろわなくなり、モデルが2回目の検索をした。モデルの応答が1回増え、入力トークンは5件のときより74%増え、費用も約41%増えた。件数を減らした分のコストが、モデルの応答回数の増加として戻ってきた
- 時間は比較に使えない：3件の lora（29.03秒）と multi-page（51.13秒）が長いのは、同じ時間帯に 503（サーバーの混雑）が続いていたためと考えられる。件数による差かどうかは確かめていない
- 各質問1回ずつの実行なので、検索語や検索回数は実行ごとに変わりうる。同じ lora でも、検索語は実行のたびに少し違った
- API キー：変更前・変更後の `run_questions.sh` の実行と、not-in-materials の再実行で、使ったキー（無料用・有料用）が同じかは記録していない。モデルは同じなので、回答とトークン数の比較には影響しない

#### 気づき・疑問

- `RAG_TOP_K` は「正しさを決める設定」ではなく、「1回の検索で集める量を決める設定」として効いていた。足りない分は、モデルが自分で検索をやり直して補った（`INSTRUCTIONS` の「必要に応じて検索を分けて根拠を集める」による）
- どの件数が得かは、聞く質問の種類で決まる。1ページで答えがそろう質問が多いなら3件、複数ページにまたがる質問が多いなら5件のほうが、応答回数が増えずに安い
- 疑問：3件のときの multi-page の1回目の検索で p.40 が返っていたなら、2回目の検索は不要だったことになる。`uv run --env-file .env python -m app.retrieval "コンパクション セッション メモリ 長期メモリ 日々のメモ"` を `RAG_TOP_K = 3` で実行すれば確かめられる

#### 4. 失敗した1問だけを手で再実行する

`run_questions.sh` は3問をまとめて実行するので、1問だけのときは `app.agent` を直接実行した。直接実行するときは `--env-file .env` を自分で付ける。

```bash
# PYTHONIOENCODING=utf-8 で、出力を UTF-8 で書かせる
# --env-file .env で、.env の API キーを渡す
# 出力をファイルに保存する（2>&1 で、エラーの出力も同じファイルにまとめる）
PYTHONIOENCODING=utf-8 uv run --env-file .env python -m app.agent --trace "今回作ったRAGの実測平均応答時間と正答率を教えてください" > "lectures/05/results/20261122_基礎_topk3/not-in-materials_再実行.txt" 2>&1
```

ここに至るまでに2回失敗した。

- **コマンドが3行に分かれた**：長いコマンドを、画面の折り返しのまま貼り付けたため、bash が改行ごとに別のコマンドとして実行した。質問がないまま `app.agent` が動き、`質問を指定してください` で止まった（API は呼ばれていない）。1行で貼るか、行末に `\` を付けて続きの行だと示せば防げる

  ```text
  agent.py: error: 質問を指定してください
  bash: 今回作ったRAGの実測平均応答時間と正答率を教えてください: command not found
  ```

- **保存したファイルが文字化けした**：`| tee` で保存したところ、ファイルが Shift_JIS（cp932）で書かれ、UTF-8 として開くと化けた。Windows の Python は、出力先がパイプやファイルのとき、OS の既定の文字コード（日本語の Windows では cp932）で書くため。`run_questions.sh` の中では `PYTHONUTF8=1` と `PYTHONIOENCODING=utf-8` を設定しているので化けない。手で実行するときは、上のコマンドのように `PYTHONIOENCODING=utf-8` を先頭に付ける

文字化けしたファイルを UTF-8 に変換しようとしたとき、Git Bash に `iconv` がなかったため、ファイルが空で上書きされた。1回目の再実行の本文はこのときに失われたので、もう一度実行した。化けずに残っていた数値（入力 2,868 tokens、`lec02-main-p013` を1件目に取得）は、2回目（2,865 tokens、同じページ）とほぼ同じだった。
