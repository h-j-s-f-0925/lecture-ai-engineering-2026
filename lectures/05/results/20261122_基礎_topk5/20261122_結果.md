# multi-page

質問: 第3回の例では、コンパクションとセッションをまたぐメモリはどう違いますか。日々のメモはすべて長期メモリに入りますか

期待するふるまい: コンパクションは同じセッションの中で古い履歴を要約に置き換える。メモリは外の保存先にあり、セッションをまたいで引き継ぐ。日々のメモは全部は入らず、見直し（dreaming）で基準を超えたものだけが長期メモリに移る。根拠は第3回 p.39・p.40（p.13 も可）

## vector
```bash
$ uv run --env-file .env python -m app.agent --trace "第3回の例では、コンパクションとセッションをまたぐメモリはどう違いますか。日々のメモはすべて長期メモリに入りますか"
[model] gemini-3.5-flash-lite
第3回の資料に基づき、コンパクションとセッションをまたぐメモリの違い、および日々のメモがすべて長期メモリに入るかについて回答します。

### 1. コンパクションとセッションをまたぐメモリの違い
* **コンパクション（コンテキストの中 / 同じセッション）**
  * **内容**: 古い履歴を要約に置き換えて、限られたコンテキストの中に詰め込む仕組みです（第3回・PDF p.39）。
  * **特徴**: 1つのセッション（コンテキストの中）で有効であり、要約に置き換えた範囲の画像や文書は失われます（第3回・PDF p.39, 65）。
* **セッションをまたぐメモリ（外の保存先）**
  * **内容**: メモリツールや自動メモリなどを用いて、セッションを越えて情報を保持する仕組みです（第3回・PDF p.39）。
  * **特徴**: エージェントが自分でメモを書いたり、ファイルや外部の保存先に保存したりすることで、次回の会話（セッション）のコンテキストに読み戻すことができます（第3回・PDF p.39）。

---

### 2. 日々のメモはすべて長期メモリに入りますか？
* **いいえ、すべては入りません。**
* OpenClawの実装例では、日々のメモ（`memory/日付.md`）は毎晩自動で見直され（dreaming）、以下のステップを経て整理されます（第3回・PDF p.40）。
  1. **集める**: 重複を除いて候補を並べる
  2. **見比べる**: 何度も出てくるテーマを探す
  3. **移す**: 基準を超えたものだけ残す
* そのため、一度きりの調べものは日々のメモに残るだけであり、基準を超えたものだけが `MEMORY.md`（長期メモリ）に移されるため、すべてが長期メモリに入るわけではありません（第3回・PDF p.40）。
```
