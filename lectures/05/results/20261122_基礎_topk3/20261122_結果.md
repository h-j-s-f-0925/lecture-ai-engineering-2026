期待するふるまい: LoRA は元の重みを固定し、小さな行列 A・B（低ランクの差分）だけを学習する。QLoRA は元の重みを 4bit に圧縮する。根拠は第2回 p.52（p.51 も可）

```bash
* **LoRAは何を固定し、何を学習するか**
  * **固定するもの：** 元の重み $W$（本体）は固定して学習しません（第2回・PDF p.52）。
```

# multi-page

質問: 第3回の例では、コンパクションとセッションをまたぐメモリはどう違いますか。日々のメモはすべて長期メモリに入りますか

期待するふるまい: コンパクションは同じセッションの中で古い履歴を要約に置き換える。メモリは外の保存先にあり、セッションをまたいで引き継ぐ。日々のメモは全部は入らず、見直し（dreaming）で基準を超えたものだけが長期メモリに移る。根拠は第3回 p.39・p.40（p.13 も可）

## vector
```bash
$ uv run --env-file .env python -m app.agent --trace "第3回の例では、コンパクションとセッションをまたぐメモリはどう違いますか。日々のメモはすべて長期メモリに入りますか"
[model] gemini-3.5-flash-lite
第3回の資料におけるコンパクションとセッションをまたぐメモリの違い、および日々のメモの扱いについて、資料に記載されている内容を整理して解説します。

### 1. コンパクションとセッションをまたぐメモリの違い

* **コンパクション（同じセッション内）**
  * **役割・動作:** 1つのセッション（コンテキストの中）において、古い履歴を要約に置き換えることで履歴を詰め、コンテキストの容量不足を防ぐ仕組みです（第3回・PDF p.39、p.65）。
  * **対象:** あくまで同じセッション内の古いやり取りが対象となります。

* **セッションをまたぐメモリ（外の保存先）**
  * **役割・動作:** セッションが終了してやり取りがリセットされても、次回のセッションへ情報を持ち越すための仕組みです（第3回・PDF p.39）。
  * **実装例:** Claude API のメモリツールや Claude Code の自動メモリ（自分でメモを書き、毎回先頭200行か25KBまでを読む仕組み）、あるいは OpenClaw のようにファイルを保存先として利用する仕組みなどがあります（第3回・PDF p.39）。

---

### 2. 日々のメモはすべて長期メモリに入りますか？

* **すべては入りません。**
* OpenClaw の実装例（第3回・PDF p.40）では、日々のメモ（`memory/日付.md`）として一度すべてが記録されますが、毎晩の自動見直し（dreaming）のプロセスを経て、以下のステップで取捨選択されます。
  1. **集める:** 重複を除いて候補を並べる
  2. **見比べる:** 何度も出てくるテーマを探す
  3. **移す:** **基準を超えたものだけ**を長期メモリ（`MEMORY.md`）に残す
* その結果、**一度きりの調べものは日々のメモに残るだけで、長期メモリには入りません。** これにより、長期メモリが膨らまないように設計されています（第3回・PDF p.40）。
```
