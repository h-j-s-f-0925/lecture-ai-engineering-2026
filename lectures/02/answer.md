## 宿題
- 取り組んだレベル：基礎
- 変えた設定やデータ：
  - 1回目（元の設定）は学習率`lr=2e-4`で実行した。
  - 2回目は学習率だけを`lr=1e-4`に変更して再学習した。
  - 基盤モデル、LoRAランク、エポック数、学習・評価データは変更していない。
  - セッションを再起動して、それぞれ独立に学習・評価した。

- 結果（比較表や数字）：
  | 指標                 | 1回目（元の設定） | 2回目（変更後） |
  | ------------------ | --------: | -------: |
  | 学習率 `lr`           |    0.0002 |   0.0001 |
  | 学習前 `format_rate`  |     9.52% |    9.52% |
  | 学習前 `content_rate` |        0% |       0% |
  | 学習後 `format_rate`  |      100% |     100% |
  | 学習後 `content_rate` |    90.48% |   90.48% |
  | 最終Training Loss    |  0.013817 | 0.032587 |
  | 学習時間               |    240.5秒 |   238.9秒 |
  | 学習ステップ数            |        40 |       40 |

  - 学習率を半分にした結果、最終Training Lossは高くなったが、21問の評価における形式遵守率と内容正解率は変わらなかった。
  - ただし、不正解になった質問は異なっていた。
    - 1回目：「成績はいつ出ますか」「オフィスアワーは事前予約が必要ですか」
    - 2回目：「PDF以外でも出せますか」「オフィスアワーは事前予約が必要ですか」
  - 1回目では誤って断定した「成績はいつ出ますか」に対し、2回目では正しく確認を求められた。
  - 一方、2回目では「PDF以外でも出せますか」に対し、FAQに提出形式の指定があるにもかかわらず、確認が必要と回答した。
  - この結果から、Training Lossが低いほど必ずしも評価時の正解率が高くなるわけではないと分かった。また、正解率が同じでも失敗の内容は異なるため、個別の回答を確認することが重要だと考える。

- ファインチューニングが向く場面・向かない場面についての考察：
  - 向く場面：JSONのような決まった形式で回答させたい場合や、`needs_review`のような項目を含む回答パターンを学習させたい場合に向いていると考える。今回も、学習後は形式遵守率が100%になった。
  - 向かない場面：FAQの内容が頻繁に変わる場合や、最新情報を根拠に正確に回答する必要がある場合は、ファインチューニングだけでは不十分だと考える。今回もFAQにない質問に誤って断定する失敗が残った。
  - そのため、回答形式や振る舞いの調整にはファインチューニングを使用し、回答の根拠となる情報はRAG（検索拡張生成）などで取得する方法が適切だと考える。
