# 第1回 宿題（実装）：会話履歴を保つ

`app/ask.py` を改修し、質問を続けても前の会話を参照できるようにします。履歴をプロセス内に保持し、各質問と回答を次のAPI呼び出しにも含めるのが目標です。

## 進め方

1. `app/ask.py` の質問処理と、Gemini APIへ入力を渡している部分を確認します。
2. 質問・回答を会話履歴として保存し、次の質問と一緒に送る処理を追加します。
3. 引数なしで起動したときに質問を繰り返し受け付け、終了コマンドで対話を終えられるようにします。
4. 複数の質問を続けたとき、後の質問で前の内容を参照できることを確認します。
5. APIを実際に呼ばないテストで、履歴の引き継ぎと終了動作を確認します。

このリポジトリの実装では、対話モードの終了コマンドは `/exit` と `/quit` です。履歴は実行中のプロセス内だけに保持され、プログラムを終了すると消えます。

## 動作確認

テストを実行します。

```bash
uv run pytest -q
```

手動でAPIを使って確認する場合は、リポジトリのルートから次を起動します。APIキーが必要です。

```bash
uv run python -m app.ask
```

最初の質問をした後、別の質問を挟み、「最初の質問は何でしたか？」などと尋ねます。回答が前の会話を参照しているか確認してください。APIキーをコマンドや提出ファイルに書かないでください。

## `answer.md` にまとめる

[answer.md](../answer.md) には、変更した内容、履歴が引き継がれることを確かめた方法と結果、テスト結果、実装して気づいたことを書きます。会話履歴だけでは、モデルが知らない講座固有の情報までは補えない点も考察できます。
