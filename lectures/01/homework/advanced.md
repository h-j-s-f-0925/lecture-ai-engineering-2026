# 第1回 宿題（発展）：応答時間とtoken数を比較する

この宿題では、複数モデルに同じ質問を送り、応答時間・token数・失敗の有無を比べます。**まずは以下の手順どおりに1回実行すれば十分です。**質問や回数を変更する設定は、初回には不要です。

## 1. 実行前に確認する

Gemini APIを呼び出すため、実行前に次を確認してください。

- `GEMINI_API_KEY` が設定されている
- Google AI Studioで利用tier、対象モデルの制限、課金状態を確認した
- 比較するモデルが現在利用可能である

APIキーやproject IDなどの秘密情報を質問、コマンド、レポートに書かないでください。

## 2. 実験を実行する

リポジトリのルートで、次のコマンドを実行します。

```bash
bash lectures/01/experiment/run-advanced.sh
```

既定の条件で、次の実験を行います。

- 2モデルに2つの質問を送る
- 各モデル・質問の組み合わせを3回ずつ実行する（合計12回）
- リクエスト間に2秒待つ
- temperatureはモデルの既定値を使う

## 3. 生成されたレポートを読む

実行が終わると、[`experiment/reports/`](../experiment/reports/) に実行結果のMarkdownファイルが作られます。最新のレポートを開き、「サマリー」と「試行ごとの結果」を確認してください。

サマリーの列は次の意味です。

| 列 | 見る内容 |
|---|---|
| 成功数・失敗数 | API呼び出しが成功した回数と失敗した回数 |
| 平均応答時間・中央値・最小・最大 | 成功した応答にかかった時間。通信やSDK処理も含む |
| 平均入力token・平均出力token | usage metadataが取得できた成功応答のtoken数 |

失敗した応答の時間やtoken数は成功時の平均に含まれません。失敗の詳細は「試行ごとの結果」で確認します。503は混雑などの一時的な問題の場合があり、無料枠のレート制限に達したと断定できません。AI Studioで確認した制限と、実験で実際に起きたことを分けて考えてください。

## 4. `answer.md` に結果を書く

[answer.md](../answer.md) の発展課題欄に、次の順でまとめます。

1. **実験条件**：モデル、質問、各条件の試行回数、実行間隔
2. **観測結果**：モデルごとの成功・失敗数、応答時間、入力・出力token数
3. **考察**：モデル間の違い、エラーとAI Studioで確認した制限との関係
4. **注意点**：試行回数が少ないことや混雑の影響など、結果から断定できないこと
5. **参照先**：確認したレポートの相対パス

実測値と考察を分けて書きます。今回の少数回の結果だけで、モデルの一般的な性能や無料枠の上限を断定しないでください。

## 実験条件を変更したい場合（任意）

既定条件を変える必要がある場合だけ、スクリプトのヘルプを確認してください。

```bash
bash lectures/01/experiment/run-advanced.sh --help
```

質問・試行回数・待機時間などを指定できますが、初回の実験では変更しなくてかまいません。レート制限を意図的に試すために、待機時間を短くしないでください。
