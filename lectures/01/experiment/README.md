# 第1回 基礎課題の実験レポート

同じ質問を複数回実行し、モデルごとの回答の違いを比較するためのスクリプトです。実行条件と回答全文を Markdown レポートに保存します。比較結果の要約と考察は `../answer.md` に記録してください。

## 実行前の確認

- `GEMINI_API_KEY` が環境変数に設定されていること
- リポジトリのルートで `uv` が使えること
- 比較に使うモデルが Gemini API で利用できること

API キーはスクリプトやログに書き込まないでください。

## 実行方法

リポジトリのルートから実行します。

```bash
bash lectures/01/experiment/run.sh
```

既定では、同じ質問を `gemini-3.5-flash-lite` と `gemini-3.5-flash` で各3回実行します。別のモデルを使う場合は、モデル名を引数で指定できます。指定した各モデルで3回ずつ実行します。

```bash
bash lectures/01/experiment/run.sh gemini-3.5-flash-lite gemini-3.1-flash-lite
```

## Markdown レポート

実行ごとに `reports/experiment-<UTC日時>-<一意な文字列>.md` が作られます。`report-template.md` に固定のタイトル・説明・見出しを置き、スクリプトがサマリー表、実験条件、回答全文をマーカー位置へ差し込みます。サマリー表には各回の入力・出力トークン数に加え、数値が取得できた実行だけを対象とした平均出力トークン数（対象回数付き）を表示します。回答全文はモデル別・実行回別に折りたたまれ、コードブロックとして表示されます。レポートは実行後にターミナルにも表示されます。実行に失敗した場合も出力をレポートに残し、残りの実行を続けたうえでスクリプトは失敗として終了します。

temperature は `app.ask` から現在指定できないため、このスクリプトではモデルを比較します。temperature を比較したい場合は、アプリ側で設定を指定できるようにしてから、比較条件と設定値を記録してください。

## `answer.md` に書くこと

生成されたレポートを確認し、実験条件、各モデルの回答の共通点・違い、用語集の正解と照らした評価を `../answer.md` にまとめます。レポートへの相対パスも添えると、考察の根拠をたどれます。3回の結果だけでモデル全体の性能を断定せず、今回の実行で観察した傾向として記述してください。
