## 宿題

- 取り組んだレベル：基礎
- やったこと：モデル、temperature を切り替えて出力を確認した。

- 取り組んだレベル：実装
- やること：app/ask.py を改修し、会話履歴を保ったまま続けて質問できるようにする
- やったこと：
    - 引数なしで起動すると、`/exit` または `/quit` まで質問を続けられる対話モードを実装した。
    - 質問と回答をプロセス内の履歴に追加し、次の質問と一緒に Gemini API へ送るようにした。
    - 入力全体・回答のトークン数に加え、履歴だけのトークン数も表示するようにした。履歴の計数には Gemini API の Count tokens API を使った。
    - API通信をモックしたテストで履歴の引き継ぎと終了コマンドを確認し、`uv run pytest -q` で18件成功した。
- 結果：
    - 対話で「LoRAとは何ですか」と質問した後、別の質問を挟んで「最初の質問は？」と尋ねると、「LoRAとは何ですか」と回答した。前の質問が後続ターンで参照されることを確認できた。
    - 手動実行では、最初の質問で入力6・出力548トークン、次の質問で入力576・出力298トークン、3つ目の質問で入力880・出力15トークンと表示された。これは履歴トークンを別表示する変更前に記録した実行結果である。
- 気づき・疑問：
    - 会話履歴はアプリのメモリ上に保持され、プロセスを終了すると失われる。履歴を次の質問と一緒に送ることで、モデルが過去の内容を参照できる。
    - 入力トークン数は今回の質問だけでなく、送信した履歴を含む入力全体の数である。`len(history)` で得られる発話数とは異なり、履歴だけのトークン数を知るにはCount tokens APIで計数する必要がある。
    - 履歴を個別に計数するAPIリクエストは回答を生成しないが、追加のリクエストとなるため、レート制限には注意が必要である。
    - AIE2026の「3レベル」については、モデルが講座資料を参照できないため正しい内容を答えられず、一般論を推測して回答した。会話履歴を保持する機能だけでは、モデルが知らない講座固有の情報を補えない。

- 取り組んだレベル：発展
- やること: 応答時間とトークン数を計測し、複数のモデルや質問で比較する。無料枠のレート制限との関係も考察する
- やったこと：
    - `app/ask.py` にAPI呼び出し時間・usage metadata・APIエラーをまとめて返す計測処理を追加した。通常の `ask()` の戻り値とCLI表示は維持した。
    - 基礎用の `lectures/01/experiment/run.sh` は、シェル学習にも使えるよう従来のBash実装として維持した。発展用は `lectures/01/experiment/run-advanced.sh` からPython runnerを起動し、モデル・質問・試行回数をまとめて実行して、専用Markdownレポートに試行結果と統計を出す。
    - 質問、試行回数、リクエスト間隔、Google AI Studioで確認した制限メモを指定可能にした。初期値は2モデル・2質問・各3回、2秒間隔とした。
    - API通信をモックした計測・集計・入力検証のテストを追加した。
- 結果：
    - 2026年11月1日に、2モデルへ2つの質問を各3回ずつ送り、合計12回実行した。詳細な条件と試行結果は[実験レポート](./experiment/reports/20261101_1843_experiment-3f3b07.md)を参照。
    - **今回の実験では、flash-liteの方が安定して回答した。** flash-liteは6回すべて成功し、応答時間は質問ごとに平均約2.9～3.2秒だった。flashは6回中2回だけ成功し、4回は503エラーだった。成功した2回の応答時間は約12.6～13.0秒だった。
    - 出力token数は、成功した試行ではflash-liteが質問ごとに平均約582～609、flashが687～718だった。ただしflashは各質問1回しか成功していないため、十分な比較とは言えない。
    - レート制限画面では、過去28日間の最大使用量／上限がGemini 3.6 FlashでRPM 4/5・TPM 63/250K・RPD 13/20、Gemini 3.5 Flash LiteでRPM 3/15・TPM 1.67K/250K・RPD 30/500と表示され、「レート上限に近づいています」という警告もあった。単位はRPMが1分あたりの要求数、TPMが1分あたりの入力token数、RPDが1日あたりの要求数である。
    - 今回の失敗は503が4回で、429は0回だった。503は、サーバーが一時的に処理できないときに返るエラーで、混雑や一時的な障害などが考えられる。429は、リクエスト数やtoken数などの利用制限に関係するエラーである。過去28日間に上限へ近づいた記録はあるが、実験した時刻の使用量は分からず、今回の503が無料枠の上限によるものかは特定できない。レート制限の説明は[AI Studio公式資料](https://aistudio.google.com/docs/rate-limits)を参照。
    - 指定した `gemini-3.5-flash` は公式資料上deprecatedで、現在は `gemini-3.6-flash` に自動転送される。そのため、実際にはflash-liteと3.6 Flashへの転送先を比較した結果である。[公式モデル情報](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash)
    - 「3レベル」の質問には両モデルとも講座固有の定義ではなく、一般論で回答した。講座資料を与えていないため、モデルは正しい講座情報を知らず、推測で答えていた。
- 気づき・疑問：
    - 応答時間は質問を送ってから回答が届くまでの時間で、通信にかかった時間も含む。
    - 指数バックオフとは、APIが一時的に失敗したとき、すぐに繰り返さず、1秒、2秒、4秒のように待ち時間を延ばして再試行する方法である。今回は再試行をせず、エラーとして記録した。
    - 試行回数が少なく、flashの失敗も多いため、この結果だけではモデルの優劣は決められない。
