## 宿題

- 取り組んだレベル：基礎
- やったこと：モデル、temperature を切り替えて出力を確認した。
- 結果(どう変わったか)：

---

- 取り組んだレベル：実装
- やること：app/ask.py を改修し、会話履歴を保ったまま続けて質問できるようにする
- やったこと：
    - 引数なしで起動すると、`/exit` または `/quit` まで質問を続けられる対話モードを実装した。
    - 質問と回答をプロセス内の履歴に追加し、次の質問と一緒に Gemini API へ送るようにした。
    - 入力全体・回答のトークン数に加え、履歴だけのトークン数も表示するようにした。履歴の計数には Gemini API の Count tokens API を使った。
    - API通信をモックしたテストで履歴の引き継ぎと終了コマンドを確認し、`uv run pytest -q` で18件成功した。
- 結果：
    - 対話で「LoRAとは何ですか」と質問した後、別の質問を挟んで「最初の質問は？」と尋ねると、「LoRAとは何ですか」と回答した。前の質問が後続ターンで参照されることを確認できた。
    - 手動実行では、最初の質問で入力6・出力548トークン、次の質問で入力576・出力298トークン、3つ目の質問で入力880・出力15トークンと表示された。これは履歴トークンを別表示する変更前に記録した実行結果である。
- 気づき・疑問：
    - 会話履歴はアプリのメモリ上に保持され、プロセスを終了すると失われる。履歴を次の質問と一緒に送ることで、モデルが過去の内容を参照できる。
    - 入力トークン数は今回の質問だけでなく、送信した履歴を含む入力全体の数である。`len(history)` で得られる発話数とは異なり、履歴だけのトークン数を知るにはCount tokens APIで計数する必要がある。
    - 履歴を個別に計数するAPIリクエストは回答を生成しないが、追加のリクエストとなるため、レート制限には注意が必要である。
    - AIE2026の「3レベル」については、モデルが講座資料を参照できないため正しい内容を答えられず、一般論を推測して回答した。会話履歴を保持する機能だけでは、モデルが知らない講座固有の情報を補えない。
